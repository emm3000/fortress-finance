# JAA v1 - Product requirements

- Status: Accepted (grilling with the owner, 2026-10-05)
- Decisions: ADR 0005 (sync v2), 0006 (game rules and Liquidation v2), 0007 (rebuild per feature), 0008 (design pipeline). Terms: `CONTEXT.md`.
- Numbers marked _tunable_ are proposals; change them here and in the domain constants, never by reopening the rule.

## Problem

The current app loses or corrupts data and its game does not work:

- An ack after a concurrent edit deletes the newer queued write: the queue upsert keeps the same id (`db/syncQueue.repository.ts:40-48`) and `markSucceeded` deletes by id (`services/sync.service.ts:185`).
- Conflicts resolve by device clock (`supabase/migrations/202603110011_h15_sync_acknowledged_operations.sql:71-76`), while trigger `set_updated_at` overwrites `updated_at` with server time (`202603110001_h2_baseline.sql:150,163`).
- Pull overwrites rows with pending writes (`db/transaction.repository.ts:212`); an offline insert keeps its old client `updated_at` (`h15:100`) and is never pulled by a device whose cursor is newer (`h15:138`).
- `last_sync_timestamp` is global (`services/sync.service.ts:152,210`) and logout keeps SQLite (`store/auth.store.ts:64-69`).
- Row write and queue write are separate statements (`db/transaction.repository.ts:51-67`, `147`, `185`).
- Dates mix local noon (`app/(main)/new-transaction.tsx:43`), UTC ISO (`db/transaction.repository.ts:227`), UTC month bounds (`:243`) and local periods (`hooks/useCurrentPeriod.ts:10`).
- Money is a float (`REAL`, `Number()`), unbounded on the client and `numeric(10,2)` on the server (`h2_baseline.sql:65`): one oversize amount fails the whole sync RPC on every retry.
- Users can write `castle_states` and `user_wallets` (`202603110002_h3_rls_policies.sql:22-23`).
- Liquidation never raises a Streak from 0 (`202603110007_h13_daily_liquidation_rpc.sql:109-116`) and any signed-in user can call it (`:201`).
- The push dispatcher re-picks `FAILED` rows forever (`supabase/functions/expo-push-dispatcher/index.ts:58,164`).

## Goals

1. A Transaction or Budget written on any device reaches every other device of the same user, with no silent loss.
2. The game rewards the two habits that matter: logging daily (Streak) and staying inside the monthly budget (Castle HP, Gold).
3. Ship v1 to Google Play.

## Non-goals (v1)

iOS store release (iOS keeps building) · user-created categories · multi-currency per user · bank import · shared budgets · a separate statistics screen · migrating data from the current app · social or sign-in providers other than email + password.

## Users

One person tracking personal spending on 1-3 own devices, often offline (commute, low signal), Spanish-speaking, in a single local currency.

## Requirements

Each requirement is done when its acceptance criteria hold on an Android release build.

### Data and sync (ADR 0005)

- **R1 Clean cut.** Supabase and local SQLite are reset to a new baseline; no data migration. AC: first launch of v1 over an old install drops the old local tables and opens an empty v1 database at `user_version = 1`.
- **R2 Multi-device.** AC: a Transaction created offline on device A appears on device B after both sync, regardless of either device's clock.
- **R3 Arrival order wins; delete wins.** AC: two edits of one Transaction keep the one the server received last; an edit arriving after a delete is rejected and the row stays deleted on every device.
- **R4 No silent loss.** AC: every queued operation ends as applied or rejected-with-reason; a rejected operation is visible in Perfil; one invalid operation does not block the rest of the batch.
- **R5 Offline-editable.** Transactions, the Budget plan and the "Hoy sin gastos" check-in work offline. Notifications, preferences, purchases (Mejoras, Escudos) and profile edits are online-only and say so when offline.
- **R6 Money.** Integer minor units of the user's single currency; amount > 0 and ≤ 100,000,000,000 minor units, validated on client and server. AC: no float column or `Number()` coercion of money remains.
- **R7 Dates.** A Transaction's date is a `YYYY-MM-DD` local calendar date; a Period is `YYYY-MM` derived from it. AC: a Transaction logged at 23:30 local stays on that day on every device and on the server.
- **R8 Logout.** Clears local SQLite, the sync cursor, the query cache and unregisters the push token. AC: user B signing in on A's phone sees none of A's data.

### Game (ADR 0006)

- **R9 Streak.** Consecutive local days that count; a day counts with at least one Transaction (expense or income) or a "Hoy sin gastos" check-in.
- **R10 Castle HP** reflects the monthly total budget only. Category limits never change HP.
- **R11 Damage is visual.** States `HEALTHY` / `UNDER_ATTACK` / `RUINS` change the art; purchased Mejoras are never lost; HP is 100 on day 1 of every month.
- **R12 Gold** is earned per day within budget and spent on Mejoras and Escudos.
- **R13 Income** shows in balances, counts for Streak, never affects HP or Gold.
- **R14 Server authority.** Liquidation runs per user at local midnight, callable only by `service_role`; users cannot write Gold, HP, Castle, Wallet, ledger or notification logs. AC: an authenticated `update` on those tables or a call to the Liquidation RPC fails.
- **R15 Late entries.** Records for a liquidated day that sync within 48 h of its Liquidation repair the Streak (favorable only); Gold of closed days never changes; HP is always recomputed from all data of the month.
- **R16 Feedback.** After logging: toast, haptic, Castle reaction and HP preview computed locally. On app open: yesterday's Parte de batalla if unseen.

## Game rules (numbers _tunable_)

- **Castle HP** (0-100), for evaluated day `d` of a month with `D` days, total budget `B`, month-to-date expenses `s` through `d`:
  - `remainingBudget = max(0, B - s) / B`, `remainingMonth = (D - d) / D`.
  - `HP = round(100 * min(1, remainingBudget / remainingMonth))`; on the last day (`remainingMonth = 0`) `HP = 100` if `s <= B`, else `0`.
  - Reading: spending on or under pace keeps 100; the Castle falls as you spend ahead of the month.
  - States: `HEALTHY` HP >= 50, `UNDER_ATTACK` 1-49, `RUINS` 0.
- **Asignación diaria** (shown as "Disponible hoy"): `max(0, B - s_before_d) / (D - d + 1)`.
- **Day within budget**: the day's expenses <= its Asignación diaria and `s <= B`.
- **Gold**: 10 per day that counts for the Streak and is within budget; +5 when the resulting Streak >= 7. Inactive days earn nothing.
- **Escudo**: 60 Gold, hold at most 2. Consumed automatically at Liquidation for a day that does not count while Streak > 0; the Streak holds (no +1). Returned if a 48 h repair makes that day count.
- **Mejoras**: 4 lines, 3 tiers each, bought in tier order, permanent: Murallas, Torres, Puerta, Estandartes. Tier prices 100 / 250 / 500 Gold (3,400 for all 12).
- **Parte de batalla** for day `d`: whether it counted, Streak before/after, Escudo used, Gold earned, HP and state at close.

## Screens

Every data screen has four required states: loading (skeleton), empty (illustration + one action), error (Spanish message + "Reintentar"), offline (cached data + banner "Sin conexión: se sincronizará al volver"). Online-only actions are disabled offline with that reason.

- **Auth**: Iniciar sesión, Crear cuenta, Recuperar contraseña. Supabase errors map to Spanish messages; no raw English text reaches the UI.
- **Onboarding** (first sign-in): 1 Moneda (PEN, USD, MXN, COP, CLP, ARS, EUR; default from device locale) → 2 Presupuesto del mes (required total; optional Límites with suggestions) → 3 Castle introduction (HP, Racha, Oro, Escudos in one screen each or a carousel).
- **Tabs** (native tabs) plus a central primary button **Registrar** (modal: Gasto/Ingreso, amount keypad, category grid, date defaulting to today, note).
  - **Castillo** (home): Castle art with Mejoras layered, state, HP bar, Racha, Oro, Escudos, "Disponible hoy", Parte de batalla card, "Hoy sin gastos" button (only today, hidden once the day counts), entry to the Mejoras shop. Empty: never (a new user sees a full-HP Castle).
  - **Crónicas**: segment Movimientos (Transactions grouped by day, month picker, type filter, edit, delete with confirmation, pending/rejected sync badge) and Partes (Parte de batalla history; replaces the alerts center).
  - **Presupuestos**: current month total vs budget, category Límites with 80%/100% states, edit plan (applies from the current month), monthly Resumen (spend by category vs Límites, total vs budget, ingresos − gastos, vs previous month), month picker for past Resúmenes.
  - **Perfil**: email, currency (read-only in v1), notification toggles, sync status (pending, rejected operations with reason and "Descartar"), Cerrar sesión.
- **Theme**: light and dark from the system setting; semantic tokens only, WCAG AA contrast (ADR 0008).

## Notifications

Spanish copy, sent in the user's timezone, each type toggleable in Perfil:

1. **Racha en riesgo**: 20:00 local (_tunable_), only if the server has no Transaction or check-in for today and Streak > 0.
2. **Presupuesto 80% / 100%**: once per Period, scope (total or category) and threshold, when synced expenses cross it.
3. **Parte de batalla**: 09:00 local (_tunable_), summary of yesterday; can be disabled.

Dispatcher: at most 5 attempts with backoff, then terminal `DEAD`; per-token results (an invalid token is removed, the others still send); a failure never re-picks a terminal row.

## Phases

1. **Data + sync v2 foundation** (mostly wave-of-one): new Supabase baseline, SQLite migration runner, categories, money/date types, Transactions and Budget plan on sync v2, logout wipe, auth error mapping. Exit: R1-R8 pass on two Android devices with skewed clocks; old `db/`, `services/sync.service.ts` paths for these entities deleted.
2. **Design** (no code, parallel with 1): JAA Design System artifact, screen designs in a Claude Design canvas covering every screen and state above, asset issues filed as `ready-for-codex`. Exit: owner signs off the canvas; tokens exported for light and dark.
3. **Liquidation v2 + UI rebuild** (waves): game schema and RPCs, hourly scheduler, notifications, then screens per tab. Exit: R9-R16 and every screen state pass; Play internal testing track build installed from the store; no hex color literal outside `tailwind.config.js` and the token module.
